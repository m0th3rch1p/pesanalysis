# QVAC integration (for judges)

Pesanalysis is an offline-first personal finance ledger for Kenya. The core AI features run on the
phone with QVAC (Tether's local AI stack). Nothing in the demo requires a network connection.

## Where QVAC is used
| File | Capability | Model | Role |
|---|---|---|---|
| `apps/mobile/src/qvac.ts` | all QVAC calls (single surface) | — | lazy loader, CPU-only, local paths, crash marker |
| `apps/mobile/src/narrate.ts` | text generation + translation | Qwen3-0.6B Q4, TranslatePsy-AfriSLM-0.8B Q4 | explain a deterministic finding; translate to Kiswahili |
| `apps/mobile/src/ai/sms-worker.ts` | constrained JSON extraction | Qwen3-0.6B Q4 | propose fields for an unknown financial SMS (validated by code) |
| `apps/mobile/src/components/TxDetail.tsx` | OCR | OCR latin_g2 + CRAFT | read a receipt photo into a note |
| `apps/mobile/src/screens/Diagnostics.tsx` | model setup and self-test | all | download/stage models, run offline checks |

Deterministic code always decides: numbers come from regex/arithmetic parsers, model output is
untrusted data that must pass `packages/core/src/ai/*` validators, and an accepted proposal is only
ever a **pending** transaction the user confirms. A wrong model answer cannot move money or change
a balance.

## Versions and files
- `@qvac/sdk` 0.22.0, `react-native-bare-kit` 0.16.0, `@qvac/fabric-android-arm64` 0.22.0
- Worker bundle: `apps/mobile/qvac/worker.bundle.js`, regenerated by `apps/mobile/scripts/bundle-qvac.sh`
  (plugins: completion, decision, OCR). It is rebuilt from the installed SDK; it contains no user data.
- Android: minSdk 29, arm64-v8a only, CPU inference (`device: 'cpu'`). The test device is an itel
  S688LN (Unisoc UMS9360, ARM Mali-G57, 8 GB RAM, Android 15). QVAC's documented GPU acceleration
  targets Adreno 700+ / Vulkan, so the demo runs on CPU.

## Models and setup
Models are downloaded once (network on) and then loaded from local paths with `modelFitPolicy: 'off'`,
so registry lookups never happen at demo time. Download steps: **More → On-device intelligence → Open model setup** (also offered after a missing-model Explain).

| Model | File | Size | Licence | Source |
|---|---|---|---|---|
| Qwen3-0.6B Q4_0 | `Qwen3-0.6B-Q4_0.gguf` | ~382 MB | Apache-2.0 | QVAC registry `QWEN3_600M_INST_Q4` |
| TranslatePsy-AfriSLM 0.8B Q4_K_M | `TranslatePsy-AfriSLM-0.8B-Q4_K_M-imat.gguf` | ~672 MB | Apache-2.0 | https://huggingface.co/qvac/TranslatePsy-AfriSLM-0.8B-Q4-GGUF |
| OCR latin_g2 | `latin_g2.gguf` | ~15 MB | Apache-2.0 (EasyOCR) | QVAC registry `OCR_LATIN` |
| CRAFT detector | `craft_mlt_25k.gguf` | ~83 MB | MIT (CRAFT) | QVAC registry `OCR_CRAFT` |

The app verifies sizes/SHA-256 where the registry publishes them and shows free storage before
downloading. Models can also be staged over USB storage for an offline install.

## Offline proof
1. Download/stage the models, then enable airplane mode.
2. Open the app and run More → On-device intelligence, or Diagnostics → AI benchmark (offline): each installed model loads and answers.
3. Create or open a transaction, tap Explain: the narration is rewritten on the phone.
4. Add a receipt photo and tap Read receipt: OCR and parsing run locally.
5. Delete the Wi-Fi/data routes and repeat; no feature in the demo path makes a network request.

## Measured caveats (honest limits)
- **Laya was measured and is not shipped in the AI path.** On a real-shaped message ("FAMILY BANK:
  Ksh 500.00 sent to JANE DOE ... Ref FB123456") the 3-way gate gave is_money 0.614, direction split
  0.28/0.36/0.36, and the binary variant answered "not money" with p=0.902 and direction "in" (wrong).
  A gate that confident and that wrong would lose real transactions, so the app does not use it. Laya's
  card already warns it is uncalibrated and weak on Swahili (0.210 MASSIVE). The model remains available
  in the developer lab for further calibration work, not in the demo path.
- **Measured on the itel S688LN (29 Oct, CPU, airplane mode for generation):** Qwen3-0.6B Q4 loads in
  2.5-8.4 s, generates at 7-20 tok/s; narration 5-18 s; Kiswahili translation (Qwen + AfriSLM) 21-30 s;
  receipt OCR 78-82 s and correctly reads TOTAL 950.00 (confidence 0.75) from a synthetic till slip;
  encrypted backup 0.65 MB takes 11-27 s (Argon2id) and restore 17-18 s for 1,704 rows across 23 tables.
- **Unknown-SMS extraction on device:** the prefilter + Qwen + validators proposed the synthetic bank
  debit as a pending transaction in 7-9 s. Validator examples from the same run: a failed-payment SMS
  was rejected (`amount_invalid, direction_no_keyword_evidence, ref_wrong_shape`) and a direction
  contradiction was caught (`direction_contradicts_keywords`); direction is now decided by wording,
  not by the model.
- TranslatePsy-AfriSLM's model card states it is not validated for high-stakes or financial use. We
  translate explanation text only, with all numbers/entities masked, verified afterwards, and an
  English fallback on any mismatch.
- No model is required for the ledger: parsers, totals, budgets, floats, alerts, habits and expected
  flows are deterministic. Without models the app degrades to those features with clear labels.
- **Benchmark tool (30 Oct 2026):** Diagnostics → “AI benchmark (offline)” runs synthetic explanation,
  Kiswahili, receipt and unknown-SMS jobs against installed models and writes `ai-benchmark.json`
  (p50/p95, validator pass rate, model names). It never sends data; a missing model is reported, not
  substituted. Measured on the itel after a fresh download: English explanation n=5, p50 5,650 ms,
  p95 19,205 ms, validator pass 100%; Kiswahili n=3, p50 8,925 ms, p95 14,681 ms, pass 67% (one
  translation rejected by the guard and fell back); receipt OCR n=1, 15,606 ms, pass 100% on the
  synthetic slip. Unknown-SMS extraction had no queued live candidate at that moment; synthetic
  extraction/validator tests are in `packages/core/test/ai-*`.
